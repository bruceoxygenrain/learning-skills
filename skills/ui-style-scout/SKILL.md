# 组件样式搜索与选型

帮用户逛组件网站、筛选参考并完成选款。默认交付 3～5 个有明显差异的候选；用户指定数量、来源、风格或已授权实现时，以用户要求为准。使用用户的语言，默认中文。

## 范围与参考资料

覆盖基础控件、复杂交互、移动端组件和局部组合界面。清单是检索入口，不是能力白名单；遇到新组件，拆成视觉结构和交互模式继续搜索，不要求用户修改 skill。

- 识别组件、同义词与关键状态：按需查阅 [组件与状态地图](references/component-map.md) 中相关行。
- 选择网站：查阅 [来源地图](references/source-map.md)，只用相关技术栈和组件领域的分组。
- 开始搜索或需要截图：查阅 [检索与预览规则](references/search-and-previews.md)。
- 组织候选或用户继续选款：查阅 [交付与后续处理](references/selection-format.md)。

## 1. 理解输入，尽快开始

接受截图、局部裁剪、组件名称、自然语言、链接，或它们的组合。先看用户给的图片；本地图片用图片查看工具，已显示在会话中的图片直接分析。网页链接用可用的搜索、读取或浏览器工具查看实际内容。

从上下文形成一份简短检索意图：

- 组件的用途与交互类型，例如表单选值、搜索建议、执行命令。
- 参考中的形状、密度、配色、边框、层次、图标和可见状态。
- 用户更想要相似款、风格变体、升级现有组件，还是自由探索。
- 已知的平台、技术栈、现有组件库、页面风格与交互需求。

沿用会话中已确定的信息。有项目时，仅在适配确有需要时读取包声明、主题变量或有关组件；不为找款遍历整个仓库。没有项目信息也可以先给样式，标注技术适配待确认。

仅在组件语义歧义会明显改变搜索结果时提一个必要问题，其余信息用明确的合理假设继续。用户只说“下拉框”时，可以先按表单选择器搜索；需要区分时说明 Select、Combobox 和操作菜单的用途。不要开局要求用户填写完整设计问卷。

截图用于提取参考特征；不得把推测的原站、字体、库或隐藏交互写成已确认事实。找不到原款时，继续提供相似候选并说明相似点。

## 2. 实际搜索并打开具体样例

使用当次可用的联网搜索和页面读取工具；优先使用已连接且能力足够的工具。仅列出记忆中的网站名称不能算完成搜索。

默认从多个相关网站探索，条件允许时覆盖至少 3 个独立来源。先找功能和风格都贴近的候选，再用另一类来源拓宽设计方向。无需访问来源地图的每个网站，也不要为了凑网站数推荐不合适的组件。同一设计的框架移植版不能充当多个不同风格。

每个进入最终候选的款式，尽量打开对应组件、变体或 Demo 的具体页面。记录组件名、变体、实际来源链接、观察到的状态和证据局限。搜索摘要只用于发现；无法打开或确认视觉的结果按备用线索标注，不伪装成已查看的推荐。

来源地图只是种子。遇到冷门组件、网站改名、域名迁移或候选不足时，用中英文同义词、视觉结构、交互名称和技术栈做开放搜索。发现质量更合适的新来源可以直接采用，无需扩展 skill。

## 3. 筛选兼顾美感、用途和落地成本

优先判断：

1. **用途匹配**：数据规模、选项长度、单多选、搜索、触屏与键盘场景是否适合。
2. **页面协调**：字重、字号、行高、间距、密度、颜色、圆角、边框和阴影是否能融入现有页面。
3. **关键状态**：默认、展开、聚焦、选中、禁用、加载、空结果或错误状态是否有证据支撑。
4. **技术适配**：项目能否直接使用；需要主题调整、样式迁移，还是增加明显的行为实现工作。

候选应在布局、信息层级、密度、交互呈现或视觉语言上有实质区别，仅换颜色不能凑成几个方案。允许克制、活泼、强对比、柔和、拟物、动效等方向，按用户场景挑选，不把某个审美固定成唯一答案。动效组件还要说明静态状态是否成立。

区分“有代码可参考”“可直接用于当前项目”“只作视觉参考”和“无样式交互基础”。Headless 库不自动算现成的漂亮皮肤；跨框架可借鉴视觉，但不能称为直接兼容。未查看实现或文档时，不承诺键盘、读屏、触屏或复杂状态已经完善。

费用、授权、版本、依赖和可访问性以当次官方信息为准；未核实时写“待确认”。不为了找一个控件默认替换整套组件库。

## 4. 让用户能直接比较

按交付参考展示 3～5 个候选，优先放真实预览和具体原始链接。每个候选简要说明样式差异、适用场景、与参考图或现有页面的关系、技术适配和影响选择的限制。

预览必须对应实际候选。用工具返回的原始媒体或获准展示的真实截图；缺少图时采用规则中的降级路径，并明确哪些外观或状态尚未看到。不得用生成图、凭记忆重绘的组件或无关封面冒充网站实例。

给出最推荐的一款及其理由；信息不足时给条件式建议，不制造精确评分。用户要求“再找一批”时沿用其反馈，改变来源或设计方向，避免重复同款。

## 5. 选款后的边界

只请求参考时，不创建项目、不改代码、不安装组件、不发布网站。用户选择候选只表示确认方向；结合其措辞和已有授权判断是否需要实现，不重复索取已有的授权。

用户要求“把第 2 个用到项目里”等实现动作时，保留已选款式、具体来源、变体和关键状态，进入项目既有的实施流程。读取当次可用的相关设计或开发 skill；本 skill 不替代其指令，也不要求无关的整站设计流程。

遵守当前会话与 AGENTS.md 的协作分工。对该用户，界面、样式和入口由用户手动测试；构建、类型检查、lint 和代码检查由用户安排其他 agent，实施 agent 不主动执行或委派。选型阶段只读浏览外部组件示例，是获取参考素材，不代表验证了用户项目。

无法联网或无法取得可信预览时，如实交付已知线索与缺口，不声称完成了跨站搜索、视觉查看或测试。
